# 2026-11-06 — The web build: the content packs apart from the .wasm

## User request

The game on the web (motorust.germade.dev) took very long to load, or froze
the tab. Its `.wasm` was 200.9 MB, ~130 MB of it the content packs built in.

## Implementation

- `build.rs`: on `wasm32`, the engine's pack is not built in (an empty list).
- `src/content.rs`:
  - `unpack`: reads a `content.pack` (`MRPK`, version 1, a count, then each
    file's path and bytes, lengths as little-endian u32).
  - `from_page` (wasm only): the first time a file is asked for, takes the
    bytes the page left in `globalThis.motorustContent` (`PAGE_GLOBAL`),
    copies them into the game's memory once, deletes the global and indexes
    the files by path. `try_file` looks there after what is built in (so a
    game still building its pack in keeps working).
  - `PackReader` (the asset server's `content://`): on the web, a file not in
    memory is fetched from `content/<path>` beside the page (`WEB_FOLDER`,
    Bevy's `HttpWasmAssetReader`): the songs, which are not in the pack.
- `tools/web_pack.py`: writes `content.pack` and the loose songs from the
  packs' folders, the game's first; listed in the README.
- `Cargo.toml`: `js-sys` on wasm (the version Bevy already uses).

## Verification

- `cargo test --lib content`: 11 passed, among them the pack's round trip,
  broken packs refused, and `tools/web_pack.py` writing what `unpack` reads
  (on the engine's own pack).
- `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings`
  pass; `cargo clippy --target wasm32-unknown-unknown --lib` has only the
  warning there was before (`list_beside`'s expectation).
- The game built for the web with this branch loads in headless Chromium,
  reaches its menu and fetches the menu's song loose (see the game's
  `RECORD/2026-11-06.web-content-apart.WIP.md`).
