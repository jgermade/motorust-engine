# 2026-11-04 — The game updating itself from its releases

## User request

An option to update the game from within the game itself, from the releases
on the game's site. Two decisions were put to the user; with no answer, the
recommended ones were taken:

- a mechanism of the engine's, which a game configures in its `game.ron`;
- the archives checked against the release's SHA-256 sums, not signed.

## Implementation

- `src/game_info.rs`: `GameInfo::updates`, optional (`Updates`). It holds
  three addresses, with `{version}` and `{target}` in them:
  - `latest`: a text file with the latest release's version;
  - `archive`: the platform's archive, without its ending;
  - `sums`: the release's `SHA256SUMS.txt`.
- `src/updater.rs` (`UpdaterPlugin`, desktop only):
  - **The check:** as the game starts, a thread reads `latest`. This is only
    in a release build, with `updates` given and no `MOTORUST_NO_UPDATES` in
    the environment.
  - **The notice:** if the latest is newer, the version on the start menu
    says "vX disponible: pulsa U para actualizar".
  - **U on the start menu:** a thread downloads the sums and the archive (at
    most 400 MB), with `.zip` on Windows, `-app.zip` for a game run from an
    app on macOS and `.tar.gz` otherwise. The archive must match its sum, or
    nothing is touched.
  - **The install:** the archive is unpacked into `.update` beside the game.
    The executable (or the whole app) is renamed aside with `.old` after its
    name, which a running executable may be on every system, and the new one
    is moved into its place. If that fails, the old one is put back.
  - **The restart:** the new game is started with the same arguments, and
    this one ends.
  - **The next start:** what was put aside, and the staging folder, are
    removed.
- New dependencies, desktop only: `ureq` (HTTPS, rustls), `sha2`, `tar`,
  `flate2` and `zip` (deflate).

## Verification

- `cargo +stable fmt --all --check` and
  `cargo +stable clippy --all-targets -- -D warnings`: clean.
- `cargo +stable test`: 655 passed, 0 failed, 2 ignored. New tests:
  - `versions_are_read_and_compared_as_three_numbers`
  - `each_platform_has_its_archive`
  - `an_archive_must_match_its_sum`
  - `the_start_menu_says_how_the_update_goes`
  - `an_update_takes_the_place_of_the_executable_and_puts_the_old_one_aside`
    (a real `.tar.gz`)
  - `an_update_takes_the_place_of_the_whole_app` (a real zip)
  - `a_game_with_no_updates_reads_as_ever`
- Not tried end to end: no release has a `version.txt` yet, and Windows and
  macOS were not run here.

# 2026-11-04 — The game updater: concluded

## Context

The binaries' sums moved from the GitHub release to the game's site, beside
the binaries (the game's `RECORD/2026-11-04.new-website-and-updates`): the
engine is shown only as a library, and the site and the binaries are the
game's. The user is merging `ccr-5ceb056d-y3evh6` (PR #2) and releasing the
engine.

## Implementation

- None in the engine: where the version, the archives and their sums are
  read from is the game's `game.ron` (`updates`), and its `sums` now names
  `https://motorust.germade.dev/downloads/motorust-{version}-SHA256SUMS.txt`.

## Verification

- `cargo +stable test`: 656 passed, 0 failed, 2 ignored (at `ec768dd`).
- Still not tried end to end: the first game release after this one, with
  its `version.txt` and its sums on the site, is the first an update can be
  taken from. That check is on the game's `ROADMAP.md`.
- This record is renamed to `.completed.md`.
